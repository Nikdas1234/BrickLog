# BrickLog — Entwurf

Stand 09.10.2026. Ergebnis der Befragung mit Niklas, von ihm bestätigt. Abschnitt 8 enthält

## 1. Zweck und Rahmen

- Dokumentiert **gekaufte Klemmbaustein-Sets** aller Hersteller. Keine Eigenbauten (MOCs).
- Ein Nutzer, ein Samsung-Handy. Kein Konto, kein Server, kein Sync, kein App-Store.
- Oberfläche deutsch, Preise in Euro, helles/dunkles Design nach Handy-Einstellung.

## 2. Technik

- Installierbare Web-App (PWA), offline lauffähig, installiert über Chrome auf Android.
- Auslieferung über GitHub Pages aus dem öffentlichen Repository `Nikdas1234/BrickLog`.
- Vite + Svelte + TypeScript. Daten in IndexedDB. Sicherung als ZIP-Datei.
- Projektordner `C:\Claude Projekte\BrickLog`.

## 3. Navigation

Vier Reiter am unteren Rand: **Sammlung · Wunschliste · Statistik · Einstellungen**.

| Reiter | Inhalt |
|---|---|
| Sammlung | Kachelübersicht aller Sets, die man besitzt oder besaß (Titelbild, Name, Hersteller, Status). Suche über Name und Setnummer. Filter nach Status, Hersteller, Thema. Plus-Knopf legt ein Set an. |
| Wunschliste | Kompakte Liste (kleines Bild, Name, Hersteller, Preis, Priorität). Summe aller Wunschpreise oben. Sortierbar nach Priorität oder Preis. Plus-Knopf legt einen Wunsch an. |
| Statistik | Siehe Abschnitt 6. |
| Einstellungen | Sicherung exportieren, Sicherung einspielen, Herstellerliste pflegen. |

Tipp auf ein Set öffnet die Detailseite: Stammdaten oben, Bautagebuch darunter.

## 4. Daten

### Set

| Feld | Art | Bemerkung |
|---|---|---|
| Name | Text | einziges Pflichtfeld |
| Hersteller | Auswahlliste | erweiterbar; Startwerte: BlueBrixx, Lumibricks, CaDA, Cobi, LEGO, Mould King, Pantasy |
| Setnummer | Text | |
| Thema/Reihe | Text mit Vorschlägen | schlägt bereits verwendete Werte vor |
| Teilezahl | ganze Zahl | |
| Preis | Euro | bei Wünschen der erwartete, bei Sets der gezahlte Preis |
| Kaufdatum | Datum | |
| Händler | Text mit Vorschlägen | |
| Lagerort | Text mit Vorschlägen | |
| Titelbild | Foto | jedes Foto des Sets kann Titelbild werden |
| Notiz | Freitext | |
| Status | Auswahl | Wunschliste, ungebaut, im Bau, fertig, abgegeben |
| Baubeginn, Fertigstellung | Datum | automatisch beim Statuswechsel, nachträglich änderbar |
| Shop-Link | Adresse | nur bei Wünschen abgefragt |
| Priorität | hoch/mittel/niedrig | nur bei Wünschen abgefragt |

### Tagebucheintrag

Gehört zu genau einem Set. Datum, Notiz, Bauabschnitt (Freitext, z. B. „Tüte 3“),
Bauzeit in Minuten, beliebig viele Fotos. Pflicht ist nur das Datum (vorbelegt mit heute).

### Foto

Aus Kamera oder Galerie. Gespeichert wird eine verkleinerte JPEG-Kopie mit höchstens
1600 px an der längeren Kante; das Original bleibt in der Galerie. Tippen öffnet die
Vollbildansicht zum Durchwischen.

## 5. Abläufe

- **Wunsch → Sammlung:** Knopf „Gekauft“ fragt nach Kaufdatum (vorbelegt: heute) und
  tatsächlich gezahltem Preis (vorbelegt: Wunschpreis), setzt den Status auf „ungebaut“.
- **Löschen:** Sets, Einträge und Fotos lassen sich löschen, immer mit Sicherheitsabfrage.
  Kein Papierkorb. Ein gelöschtes Set nimmt seine Einträge und Fotos mit.

## 6. Statistik

Anzahl Sets je Status, Gesamtteilezahl, Gesamtausgaben, gesamte Bauzeit, Aufteilung nach
Hersteller (Anzahl Sets und Ausgaben).

## 7. Sicherung

- **Exportieren:** eine ZIP-Datei mit allen Daten und Fotos, die das Handy über den
  üblichen Speichern-/Teilen-Weg ablegt.
- **Einspielen:** ersetzt den gesamten Bestand durch den Inhalt der Datei, nach
  Sicherheitsabfrage. Gedacht für ein neues Handy.
- Keine Erinnerung ans Sichern.

## 8. Festlegungen aus der Planung (noch kippbar)

1. **Statuswechsel:** Wechsel auf „im Bau“ setzt den Baubeginn auf heute, falls leer.
   Wechsel auf „fertig“ setzt die Fertigstellung auf heute, falls leer (und den Baubeginn,
   falls der noch fehlt). Wechsel von „fertig“ zurück auf „im Bau“ oder „ungebaut“ leert
   die Fertigstellung.
2. **Gesamtteilezahl** zählt Sets mit Status ungebaut, im Bau und fertig — nicht
   abgegebene und nicht gewünschte.
3. **Gesamtausgaben** zählen alles außer Wünschen, also auch abgegebene Sets: Das Geld
   wurde ausgegeben.
4. **Einspielen prüft zuerst, löscht dann.** Eine beschädigte oder fremde Datei führt zu
   einer Fehlermeldung, der vorhandene Bestand bleibt unangetastet.
5. **Dauerhafter Speicher:** Die App bittet Chrome beim Start, ihre Daten nicht
   automatisch zu verwerfen (`navigator.storage.persist()`). Das schützt vor dem
   automatischen Aufräumen bei knappem Speicher, nicht vor dem manuellen Löschen.
6. **Preise** werden intern als ganze Cent gespeichert, damit Summen ohne Rundungsfehler
   stimmen. Eingabe mit Komma („12,99“).

## 10. Nachtrag 09.10.2026: Lumibricks-Katalog (Version 1.1.0)

Auf Wunsch von Niklas liegt der Lumibricks-Katalog in der App. Damit ist „automatischer
Abruf von Set-Daten" aus Abschnitt 9 für diesen einen Hersteller umgesetzt.

- **Bedienung:** Im Formular „Neues Set" bzw. „Neuer Wunsch" steht oben ein Suchfeld.
  Setnummer oder Name eintippen (englischer oder deutscher Shop-Name), Treffer antippen:
  Name, Hersteller, Setnummer, Thema/Reihe und Teilezahl werden ausgefüllt, das
  Produktbild wird beim Speichern als Titelbild geladen. Alles bleibt änderbar.
- **Preis:** Nur bei Wünschen wird der Preis vorbelegt, zusammen mit dem Shop-Link. Es
  ist ein **Richtpreis**: Der Shop rechnet in US-Dollar ab und zeigt Euro nur
  umgerechnet und auf ganze Euro gerundet an. Bei Sets in der Sammlung bleibt der Preis
  leer, weil dort der tatsächlich gezahlte Betrag hingehört.
- **Namen:** Übernommen wird der englische Name, wie er auf dem Karton steht. Der
  deutsche Shop-Name dient nur der Suche.
- **Herkunft:** Öffentliche Produktliste des Shops <https://www.lumibricks.com>,
  Stand 09.10.2026, 128 Sets. Nicht enthalten: Prämienartikel und Zubehör. Bei zwei
  Sets nennt der Shop keine Teilezahl.
- **Was im Repository liegt:** nur Fakten (Nummer, Name, Reihe, Teilezahl, Richtpreis)
  und die Adresse des Produktbilds. Keine Beschreibungstexte, keine Bilddateien. Das
  Bild lädt erst dein Handy, wenn du ein Set übernimmst.
- **Aktualisieren:** `npm run katalog` ruft den Katalog neu ab (rund eine Minute),
  danach committen und pushen. Die App selbst kann den Shop nicht live abfragen, weil
  er Abrufe von fremden Webseiten nicht zulässt; deshalb ist der Katalog ein Abzug.
- **Ohne Internet:** Die Suche funktioniert, die Vorschaubilder und das Titelbild
  fehlen dann.

## 11. Nachtrag 09.10.2026: Status entfällt (Version 1.2.0)

Auf Wunsch von Niklas gibt es keinen Baustatus mehr. Das ersetzt die Statusangaben in
den Abschnitten 3 bis 6 und die Punkte 1 bis 3 in Abschnitt 8.

- Ein Set ist entweder **in der Sammlung** oder **auf der Wunschliste**. Die Zustände
  ungebaut, im Bau, fertig und abgegeben gibt es nicht mehr.
- Entfallen sind: das Statusfeld im Formular und auf der Set-Seite, die Statusmarke auf
  den Kacheln, der Statusfilter in der Sammlung, die Aufstellung „Nach Status" in der
  Statistik.
- **Baubeginn und Fertigstellung** bleiben als Datumsfelder im Formular und werden von
  Hand eingetragen. Bereits automatisch gesetzte Daten bleiben erhalten.
- **Statistik:** „Sets" zählt alle Sets der Sammlung, ebenso Teilezahl und Ausgaben.
  Früher „abgegebene" Sets zählen damit wieder bei den Teilen mit. Wer ein Set nicht
  mehr besitzt, löscht es oder vermerkt es in der Notiz.
- **Vorhandene Daten:** Beim ersten Start der neuen Fassung werden alle Sets der
  Sammlung umgestellt, nichts geht verloren. Sicherungen aus älteren Fassungen lassen
  sich weiter einspielen.

## 12. Nachtrag 09.10.2026: Android-App statt nur Web-App (Version 1.3.0)

Niklas möchte doch eine echte App. Das ersetzt die Entscheidung für die reine Web-App in
Abschnitt 2; Inhalt und Bedienung bleiben gleich.

- **Bauart:** Die vorhandene Web-App wird mit Capacitor in eine Android-Hülle gesteckt.
  Es gibt weiterhin nur einen Programmcode für Web-App und Android-App.
- **Bau:** GitHub baut bei jedem Push eine signierte APK (Niklas' Wahl: kein Android
  Studio auf dem PC). Sie liegt unter einer festen, öffentlichen Download-Adresse.
- **Installation:** APK am Handy herunterladen und antippen, nicht über einen Store.
  Aktualisieren heißt: neue APK herunterladen und drüberinstallieren.
- **Unterschiede zur Web-App:** Die Sicherung wird über den Teilen-Dialog von Android
  abgelegt statt in den Download-Ordner. Die Daten liegen im Speicher der App und sind
  vom Löschen der Browserdaten nicht mehr betroffen. Ein Service Worker ist nicht nötig,
  weil die App ihre Dateien selbst mitbringt.
- **Signaturschlüssel:** liegt lokal im Ordner `geheim` und als Secret bei GitHub. Sein
  Verlust bedeutet: keine Aktualisierung mehr ohne Neuinstallation.
- **Die Web-App bleibt** unter der bisherigen Adresse bestehen. Sie teilt keine Daten
  mit der Android-App.
